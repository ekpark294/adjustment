# 26-003 짧은 공유 링크와 정산별 미리보기 카드

- 작업일: 2026-08-05
- 대상: 한입정산 웹 애플리케이션
- 목표: 카카오톡에서 공유 링크가 미리보기 카드로 표시되도록 함

## 1. 문제

`docs/26-002`에서 만든 공유 링크는 정산 내역을 URL 해시에 담는다. 실제 정산 기준으로 약 560자다.

이 링크를 카카오톡에 보내면 미리보기 카드가 만들어지지 않고 긴 URL이 그대로 노출된다. 같은 사이트의 주소를 짧게(`https://adjustment-ten.vercel.app/`) 보내면 카드가 정상 표시되므로, OG 태그 문제가 아니라 URL 길이 문제로 확인했다.

확인 과정에서 별개의 문제도 두 건 찾아 고쳤다.

- `og:image`가 없어 카드가 만들어지지 않았다. 이미지 규격이 없으면 카카오톡은 카드를 생성하지 않는다.
- `.gitignore`에 `*.png` 전체 제외가 걸려 있어 `public/og-image.png`가 커밋되지 않았다. 로컬 빌드에서는 `dist/`에 복사되어 정상으로 보였으나 배포본에서는 404였다. `!public/*.png` 예외를 추가했다.

## 2. 구조

내역을 서버에 저장하고 짧은 식별자만 URL에 담는다.

```text
전  https://adjustment-ten.vercel.app/#s=zeJylkc1Kw1AQhV-lzHo...   560자
후  https://adjustment-ten.vercel.app/s/k3Bx9mQa                     46자
```

### 저장하는 값

`26-002`의 압축 토큰을 **그대로** 저장한다. 서버는 토큰의 내용을 해석하지 않고 문자열로만 다루므로, 인코딩과 디코딩 로직이 한 벌로 유지된다. 해시 방식과 저장 방식이 같은 코드를 공유한다.

### API

| 경로 | 역할 |
|---|---|
| `POST /api/share` | 토큰 저장 후 id 반환 |
| `GET /api/settlement?id=` | 토큰 조회 |
| `GET /s/:id` | OG 태그를 이 정산의 요약으로 바꾼 HTML 반환 |

`vercel.json`에 `/s/:id` → `/api/s?id=:id` rewrite를 추가했다. 기존 rewrite는 명시 경로만 지정되어 있어 충돌하지 않는다.

### 스토리지

Upstash Redis를 REST API로 호출한다. REST 방식이라 별도 패키지 설치가 필요 없고, `fetch`만으로 동작한다. 환경변수는 Vercel 마켓플레이스로 연결하면 자동 주입된다.

Redis를 택한 이유는 TTL이다. 보관 기간을 코드 한 줄로 강제할 수 있어 별도 만료 처리를 만들 필요가 없다.

```js
["SET", key, value, "EX", "1209600", "NX"]
```

## 3. 정산별 미리보기 카드

`/s/:id`는 정적 `index.html`을 가져와 OG 태그를 이 정산의 요약으로 교체한 뒤 돌려준다. 앱 번들은 평소대로 로드되므로 화면 동작은 동일하다.

```text
제목  한입정산 · 박성진, 박은규 외 10명
설명  총 391,000원 · 13개 메뉴 · 2차까지
```

기존 태그는 지우고 다시 넣는다. 남겨 두면 크롤러가 어느 쪽을 쓸지 정해지지 않는다.

요약 계산은 클라이언트의 계산 규칙과 일치해야 한다. 특히 개별 수량 모드에서는 참여자별 수량의 합이 총 수량이다. 실제 공유 링크로 검사해 클라이언트 계산값과 총액이 일치하는 것을 확인했다.

해시 방식으로는 이 카드를 만들 수 없다. 해시는 서버로 전송되지 않아 크롤러가 내용을 볼 수 없기 때문이다. 정산별 카드는 저장 방식에서만 가능하다.

## 4. 안전장치

### 스토리지가 없을 때

`/api/share`가 503을 반환하면 클라이언트는 `26-002`의 해시 링크를 만든다. 링크는 길어지지만 공유 기능은 멈추지 않는다. 스토리지를 연결하기 전에 배포해도 앱이 깨지지 않으며, 공유 버튼을 눌렀을 때 나오는 링크 길이로 연결 여부를 확인할 수 있다.

### 식별자

참여자 이름이 담긴 링크이므로 추측할 수 없어야 한다. 8자 무작위 문자열로 약 47비트다. `SET NX`를 써서 이미 쓰인 id면 저장이 거절되고, 그때만 다시 뽑는다.

### 공개 쓰기 엔드포인트

누구나 호출할 수 있으므로 토큰 길이를 32KB로 제한하고, IP당 10분에 30건으로 제한한다.

### 보관 기간

14일이다. 정산은 대개 며칠 안에 끝나므로 길게 둘 이유가 없고, 이름이 담긴 데이터를 오래 보관하지 않는 편이 낫다.

기간이 짧아진 만큼 만료된 링크를 여는 경우가 실제로 생긴다. 만료(404)를 일반 실패와 구분해 전용 안내 화면을 보여준다. 네트워크 오류 같은 일반 실패는 조용히 첫 화면으로 넘어간다. 만료가 아닌데 만료라고 안내하면 안 되기 때문이다.

보관 기간은 `api/share.js`, 개인정보처리방침, 만료 안내 문구 세 곳에 나온다. 값을 바꿀 때 함께 고쳐야 한다.

## 5. 개인정보처리방침

기존 방침은 "개인정보를 서버 데이터베이스에 저장하지 않습니다"였다. 공유 링크를 만들면 이름과 메뉴 내역이 서버에 저장되므로 이 문구를 그대로 둘 수 없다.

`정산 결과 공유` 항목을 추가해 다음을 명시했다.

- 공유 링크를 만들 때만 저장되며, 만들지 않으면 아무것도 저장되지 않는다
- 14일 후 자동 삭제된다
- 링크 주소를 아는 사람은 누구나 볼 수 있다
- 삭제 요청 경로

## 6. 검증 결과

- 실제 배포본에서 만든 공유 링크의 왕복 복원 확인. 12명 / 13개 메뉴 / 총 391,000원이 정확히 일치
- 서버의 요약 계산이 클라이언트 계산과 일치
- 모든 화면의 렌더 검사 통과
- `npm run build` 통과

실제 카카오톡에서 짧은 링크의 카드 표시 여부는 배포 후 확인이 필요하다.

- `api/settlement.js`: 신규. 조회

- `src/App.jsx`: `/s/:id` 처리, 만료 화면
- `src/data/siteContent/privacy.jsx`: 공유 저장 관련 항목
- `src/styles.css`: 만료 화면 스타일

## 8. 배포 절차

1. Vercel 대시보드에서 Storage로 Upstash Redis 연결. 환경변수는 자동 주입된다
2. 커밋 후 배포

API 함수 자체는 스토리지 없이도 배포되고 동작한다. 스토리지는 저장 기능에만 필요하다.

## 9. 남은 확인 사항

1. 실제 카카오톡에서 짧은 링크의 카드 표시 확인
2. 카카오 디버거로 캐시 초기화 후 정산별 카드 내용 확인
3. `og-image.png`가 1.02MB로 큰 편이다. 미리보기 로딩이 느리면 압축 검토
4. 만료된 링크 안내 화면의 실제 동작 확인
