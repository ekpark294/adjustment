# 26-002 정산 결과 공유 링크

- 작업일: 2026-08-05
- 대상: 한입정산 웹 애플리케이션
- 목표: 정산 결과를 URL로 공유해 다른 사람이 열어볼 수 있게 함

## 1. 요약

정산 결과 화면에 `공유 링크` 버튼을 추가했다. 참여자와 메뉴 내역을 URL에 담아 전달하면, 받은 사람이 링크를 열어 같은 정산 결과를 그대로 확인할 수 있다.

## 2. 저장소 없이 공유하는 방법

한입정산은 서버 데이터베이스가 없는 정적 웹이다. 정산 내역을 서버에 저장하고 짧은 링크를 발급하는 방식은 쓸 수 없으므로, 내역 자체를 URL에 담는다.

### URL 해시를 쓰는 이유

내역은 쿼리스트링이 아니라 **해시**에 담는다.

```text
https://adjustment-ten.vercel.app/#s=eyJ2IjoxLCJyIjox...
```

- 해시는 브라우저가 서버로 전송하지 않는다. 참여자 이름이 서버 접근 로그나 호스팅 기록에 남지 않으므로, 개인정보처리방침의 "서버에 저장하지 않는다"는 내용과 어긋나지 않는다.
- `vercel.json`에 별도 rewrite를 추가할 필요가 없다. 경로는 루트 그대로이기 때문이다.

### 인코딩

`JSON` 문자열을 UTF-8로 바꾼 뒤 base64url로 변환한다. `+`, `/`, `=`를 URL에 안전한 문자로 바꾸므로 메신저에서 링크가 잘리거나 깨지지 않는다.

링크를 짧게 유지하려고 두 가지를 적용했다.

- 키를 한 글자로 줄인다. `menu`는 `n`, `price`는 `c`, `members`는 `m`으로 저장한다.
- 참여자는 이름 대신 순번으로 저장한다. 같은 이름이 메뉴마다 반복되지 않는다.
- 기본값은 생략한다. 차수는 `1`이면 저장하지 않고, 전체 수량 모드에서는 개별 수량을 저장하지 않는다.

### 링크 길이

측정 결과는 다음과 같다.

```text
4명 / 5개 메뉴   →  478자
6명 / 12개 메뉴  →  1,036자
8명 / 20개 메뉴  →  1,684자
10명 / 40개 메뉴 →  3,388자
```

브라우저 주소창은 문제가 없으나, 일부 메신저는 매우 긴 URL을 자동으로 줄이거나 줄바꿈한다. 메뉴가 수십 개인 정산에서는 링크가 잘릴 수 있다. 필요해지면 압축을 추가하는 것이 다음 후보다.

## 3. 담는 내용과 담지 않는 내용

담는 항목은 참여자 목록, 메뉴별 이름·가격·수량·참여자·개별 수량·차수, 차수 사용 여부다.

임시 저장 내역은 담지 않는다. 임시 저장은 각자의 브라우저에 있는 개인 기록이며 공유 대상이 아니다.

### 이름 없이 가격만 있는 메뉴

`calculateGrandTotal`은 메뉴명이 없어도 가격이 있으면 총 주문 금액에 합산한다. 반면 메뉴별 분배 내역 표는 메뉴명이 있는 항목만 보여준다.

이 때문에 처음에는 메뉴명이 있는 항목만 링크에 담았는데, 보낸 사람과 받은 사람의 총 주문 금액이 달라졌다. 이름 없이 가격만 입력한 항목이 링크에서 빠지면서 총액이 줄어든 것이다.

지금은 **메뉴명이 있거나 가격이 0보다 큰 항목**을 모두 담는다. 화면에 보이지 않는 항목이라도 금액에 영향을 주면 그대로 옮겨야 두 사람이 같은 숫자를 본다.

## 4. 공유받은 화면

링크로 접속하면 결과 화면을 읽기 전용으로 보여준다.

- 제목이 `공유받은 정산 내역이에요`로 바뀌고, 링크의 내용을 그대로 보여준다는 안내를 표시한다.
- 인원 선택, 표 강조, 이미지 저장, 결과 복사는 그대로 쓸 수 있다.
- `이 내역으로 계속하기`를 누르면 내 정산으로 가져와 주문 내역 화면에서 이어서 수정한다. 이때 주소의 해시를 지워 원래 링크와 분리한다.
- `새로 정산하기`를 누르면 해시를 지우고 첫 화면으로 이동한다.

공유받은 내역은 `shared` 상태로 따로 보관해 내 정산 상태와 섞이지 않게 했다. 링크를 열어본 것만으로 작성 중이던 내 정산이 덮어써지면 안 되기 때문이다.

## 5. 잘못된 링크 처리

`decodeSettlement`는 다음 경우에 `null`을 반환하고, 앱은 평소의 첫 화면을 보여준다.

- base64가 깨졌거나 JSON 형식이 아닌 경우
- 버전 번호가 맞지 않는 경우
- 참여자 목록이 비어 있거나 유효한 메뉴가 하나도 없는 경우

버전 번호(`v`)를 넣어 두었으므로, 이후 저장 형식을 바꾸더라도 예전 링크를 구분해 처리할 수 있다.

## 6. 검증 결과

실제 소스를 불러와 왕복 변환을 검사했다. 확인 항목은 다음과 같다.

- 참여자 목록 보존
- 인원별 정산 금액 일치
- 총 주문 금액 일치
- 차수 사용 여부와 메뉴별 차수 값 보존
- 개별 수량의 소수 값 보존
- 이름 없이 가격만 있는 항목 보존
- 한글, 공백, 작은따옴표가 섞인 이름 보존
- 손상된 토큰과 빈 토큰에서 `null` 반환

`npm run build` 프로덕션 빌드도 통과했다.

## 7. 변경 파일

- `src/utils/shareLink.js`: 신규. 인코딩, 디코딩, 링크 생성, 해시 정리
- `src/App.jsx`: 공유 링크 판별과 읽기 전용 화면 분기, 내 정산으로 가져오기
- `src/components/ResultStep.jsx`: `공유 링크` 버튼, 공유받은 화면의 안내와 버튼
- `src/styles.css`: 공유 버튼과 안내 문구 스타일

## 8. 남은 확인 사항

1. 카카오톡, 문자 등 실제 메신저에서 긴 링크가 잘리지 않는지 확인
2. 메뉴가 많은 정산의 링크 길이 대책으로 압축 도입 검토
3. 공유 링크에 참여자 이름이 포함된다는 점을 개인정보처리방침과 사용 안내에 반영할지 검토
