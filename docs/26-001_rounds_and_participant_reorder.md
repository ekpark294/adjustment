# 26-001 차수 정산 및 참여자 목록 편집

- 작업일: 2026-08-05
- 대상: 한입정산 웹 애플리케이션
- 목표: 1차·2차 등 차수별 정산 지원, 참여자 순서 변경과 이름 수정

## 1. 요약

다음 기능을 추가했다.

1. 주문 내역 화면에서 메뉴마다 차수를 지정한다. 차수 사용 여부는 토글 버튼으로 켜고 끈다.
2. 차수가 섞인 메뉴 목록을 차수 순으로 정렬한다.
3. 참여자 화면에서 마우스와 터치 드래그로 참여자 순서를 바꾼다.
4. 참여자 이름을 눌러 바로 수정한다. 중복 이름은 적용하지 않는다.
5. 정산 결과 화면에서 차수별 데이터를 확인하고, 차수 구간을 굵은 선으로 구분한다.

## 2. 데이터 모델 변경

메뉴 항목에 `round` 필드를 추가했다.

```text
{ id, menu, price, quantity, members, quantityMode, memberQuantities, round }
```

`round`는 1 이상의 정수이며 기본값은 `1`이다. 값이 없거나 잘못된 경우 `getItemRound`가 `1`로 보정하므로, 이전에 저장한 임시 저장 내역도 그대로 불러올 수 있다.

차수 사용 여부인 `roundsEnabled`는 특정 메뉴가 아닌 정산 전체의 상태이므로 `App.jsx`에서 관리하고 주문 내역 화면과 결과 화면에 함께 전달한다.

## 3. 계산 로직

차수는 표시 및 분류 용도이며 금액 계산 공식은 변경하지 않았다. 기존 인원별 최종 금액은 모든 메뉴를 합산한 값 그대로다.

차수별 금액은 기존 계산 함수를 해당 차수의 메뉴만 걸러 그대로 재사용한다.

```text
차수별 총액   = calculateGrandTotal(해당 차수 메뉴)
차수별 인원금액 = calculateTotals(참여자, 해당 차수 메뉴)
```

`src/utils/settlement.js`에 추가한 함수는 다음과 같다.

- `getItemRound(item)`: 메뉴의 차수를 반환하며 비정상 값은 `1`로 보정
- `getMaxSelectedRound(items)`: 현재 선택된 최대 차수
- `getRoundOptions(items)`: 화면에 노출할 차수 버튼 목록
- `getUsedRounds(items)`: 실제 사용 중인 차수를 오름차순으로 반환

## 4. 주문 내역 화면

### 차수 적용 토글

`메뉴 추가` 버튼 왼쪽에 `차수 적용` / `차수 취소` 토글 버튼을 배치했다.

- 켜면 각 메뉴 카드의 제목 아래에 차수 선택 행이 나타난다.
- 끄면 선택 행과 결과 화면의 차수 표시가 모두 사라진다.
- 껐다가 다시 켜도 각 메뉴의 `round` 값은 유지되므로 이전 선택이 그대로 복원된다.

### 차수 노출 규칙

노출할 차수 개수는 다음과 같이 계산한다.

```text
노출 차수 개수 = max(2, 선택된 최대 차수 + 1)
```

즉 처음에는 `1차`, `2차`만 보이고, 어떤 메뉴든 `2차`를 선택하면 `3차`가 나타난다. `3차`를 선택하면 `4차`가 나타나는 방식으로 이어진다. 차수 목록은 개별 카드가 아닌 전체 메뉴 기준으로 계산하므로 모든 카드가 같은 선택지를 보여준다.

마지막으로 `3차`를 쓰던 메뉴를 모두 낮은 차수로 되돌리면 노출 차수도 함께 줄어든다.

### 새 메뉴의 차수 승계

`App.jsx`가 마지막으로 다룬 차수를 `activeRound`로 기억한다. 차수 버튼을 누를 때마다 이 값이 갱신되고, `메뉴 추가` 버튼은 이 값을 새 메뉴의 차수로 사용한다.

마지막 메뉴가 `2차`로 선택된 상태에서 메뉴를 추가하면 새 메뉴도 `2차`가 선택된 상태로 시작한다. 차수를 사용하지 않는 상태에서도 값은 동일하게 승계되므로, 나중에 토글을 켜도 일관된 상태가 유지된다.

목록 맨 위 메뉴의 차수를 읽지 않고 별도 상태로 둔 이유는 아래 차수순 정렬 때문이다. 정렬 후에는 목록 맨 위가 가장 최근에 추가한 메뉴가 아니라 가장 낮은 차수의 메뉴가 되므로, 목록 순서로는 직전에 다루던 차수를 알 수 없다.

`activeRound`는 화면 단계를 오갈 때도 유지되도록 `App.jsx`에 두었다. 임시 저장 내역을 불러오면 저장된 첫 메뉴의 차수로 초기화한다.

### 차수순 정렬

차수를 사용하고 메뉴가 두 개 이상이면 목록 위에 `차수순 정렬` 버튼이 나타난다.

```text
정렬 전: 1차, 3차, 2차, 1차, 1차
정렬 후: 3차, 2차, 1차, 1차, 1차
```

`1차`를 맨 아래에 두고 높은 차수를 위로 올린다. 새 메뉴가 목록 맨 위에 추가되는 기존 방식과 방향이 같다. 같은 차수 안에서는 기존 순서를 그대로 유지한다. 이미 정렬된 상태면 버튼이 비활성화되고, 안내 문구로 현재 상태를 함께 알려준다.

결과 화면의 표는 이와 반대로 `1차`부터 위에서 아래로 읽도록 정렬한다. 주문 내역은 최근에 추가한 메뉴를 위에 두는 입력 화면이고, 결과 표는 처음부터 순서대로 읽는 요약이기 때문이다.

메뉴 카드의 번호는 위치 기준(`items.length - index`)이므로 정렬 후에도 빈틈 없이 이어진다.

## 5. 참여자 화면

### 이름 수정

참여자 이름을 누르면 입력창으로 바뀌어 바로 수정할 수 있다.

- Enter 또는 포커스 이동으로 저장하고, Esc로 취소한다.
- 이미 있는 이름이면 적용하지 않는다. 입력창을 붉게 표시하고 목록 아래에 안내 문구를 보여주며 수정 상태를 유지한다.
- 빈 값이거나 기존과 같은 이름이면 변경 없이 수정 상태만 닫는다.
- 한글 입력 조합 중 Enter는 무시한다.

이름은 메뉴별 선택을 저장하는 키이므로, 이름을 바꿀 때 `people`뿐 아니라 모든 메뉴의 `members` 배열과 `memberQuantities` 객체 키도 함께 옮긴다. 이 작업을 빠뜨리면 이름을 바꾼 참여자의 선택과 개별 수량이 사라진다.

### 순서 변경 입력 방식

Pointer Events를 사용해 마우스와 터치를 같은 코드로 처리한다.

- 각 행 왼쪽에 손잡이 버튼을 추가했다.
- 터치는 손잡이에서만 드래그를 시작한다. 손잡이에만 `touch-action: none`을 적용해 목록 위에서의 세로 스크롤이 막히지 않도록 했다.
- 마우스는 버튼과 입력창을 제외한 행 어느 곳에서나 드래그를 시작할 수 있다. 이름 수정용 버튼과 입력창에서 드래그가 시작되면 이름을 누를 수 없으므로 제외 대상에 포함했다.
- 손잡이에 포커스한 뒤 위아래 방향키로도 순서를 바꿀 수 있다.

### 이동 거리 계산

행 높이와 간격의 합을 한 칸으로 보고, 포인터 이동 거리를 나눠 목표 위치를 정한다.

```text
목표 위치 = 시작 위치 + round(이동 거리 ÷ 한 칸 높이)
```

한 칸 높이는 `getBoundingClientRect`가 아닌 `offsetTop` 차이로 측정한다. `offsetTop`은 `transform`의 영향을 받지 않으므로, 직전 드래그의 복귀 애니메이션이 남아 있는 동안 새 드래그를 시작해도 값이 정확하다.

### 애니메이션 처리

전환 효과는 드래그 중에만 켠다. 드롭 시점에는 배열 순서 변경과 `transform` 해제가 같은 렌더에서 일어나는데, 이때 전환 효과가 켜져 있으면 행이 한 번 튀었다가 제자리로 미끄러지는 현상이 생긴다. 목록에 `reordering` 클래스가 있을 때만 전환을 적용해 이 문제를 막았다.

### 주문 내역과의 관계

순서를 바꿔도 주문 내역의 선택 상태는 영향을 받지 않는다. 근거는 다음과 같다.

- 메뉴의 참여자 선택은 `members` 배열과 `memberQuantities` 객체에 이름 문자열로 저장된다. 참여자 배열의 인덱스를 참조하지 않는다.
- 순서 변경은 `people` 배열만 재배치하며 `setItems`를 호출하지 않는다.

다만 `getItemParticipants(item, people)`가 `people` 순서를 기준으로 비고란을 정렬하므로, 바뀐 순서가 결과 화면의 표시 순서에 자연스럽게 반영된다. 이는 의도된 동작이다.

## 6. 정산 결과 화면

### 메뉴별 분배 내역

차수를 사용할 때 표에 `차수` 열이 추가된다.

```text
번호 | 차수 | 메뉴 | 가격 | 수량 | 인원 | 분배 금액 | 비고
```

행은 차수 오름차순으로 묶고, 같은 차수 안에서는 기존과 같이 입력 순서를 유지한다. 주문 내역 화면의 정렬 여부와 관계없이 결과 표는 항상 차수 순으로 묶어서 보여준다. 차수를 사용하지 않으면 열이 나타나지 않고 정렬도 기존과 동일하다.

차수가 바뀌는 첫 행에는 굵은 선을 올려 차수 구간을 구분한다. 표의 다른 행 구분선은 1px 옅은 회색이고 차수 구분선은 3px 강조색이므로, 어디까지가 같은 차수인지 한눈에 확인할 수 있다.

이 구분선은 `border-top`이 아니라 셀 배경(`background-image`의 단색 그라디언트)으로 그린다. 자세한 이유는 아래 PNG 저장 항목에 정리했다.

### 차수별 정산 금액

메뉴별 분배 내역 아래에 차수별 정산 섹션을 추가했다. 각 차수마다 다음 항목을 표시한다.

- 차수 번호
- 해당 차수의 메뉴 개수
- 해당 차수의 총 주문 금액
- 해당 차수에 부담 금액이 있는 참여자와 각자의 금액

인원별 정산 금액에서 특정 인원을 선택하면 차수별 카드에서도 해당 인원이 강조된다.

### 결과 복사

`결과 복사` 버튼의 텍스트에 차수별 내역을 함께 포함한다. 차수를 사용하지 않으면 기존과 동일한 형식으로 복사된다.

```text
김길동: 12,500원
이길동: 9,000원

[1차] 총 45,000원
- 김길동: 9,000원
- 이길동: 9,000원

[2차] 총 18,000원
- 김길동: 3,500원
```

## 7. PNG 이미지 저장

차수별 정산 금액 영역에 이미지 저장 버튼을 추가했다. 기존 세 영역과 동일한 방식으로 동작한다.

```text
한입정산-차수별정산금액-YYYY-MM-DD.png
```

### 화면과 저장 이미지가 달라지는 문제

`html-to-image`는 대상 노드를 복제해 SVG `foreignObject` 안에서 다시 그린다. 화면에서 멀쩡하던 요소가 저장 이미지에서만 달라질 수 있어, 두 가지를 조정했다.

**차수 구분선**: 처음에는 `border-top: 2px`로 구분선을 그렸는데 저장 이미지에서 선이 나타나지 않았다. `border-collapse: collapse` 표의 테두리는 복제 과정에서 누락될 수 있다. 테두리 대신 셀 배경으로 3px 띠를 그려 해결했다.

```css
background-image: linear-gradient(#9aab24, #9aab24);
background-repeat: no-repeat;
background-size: 100% 3px;
background-position: left top;
```

이때 `background-color`는 지정하지 않는다. 인원 선택 시 적용되는 행 강조 색이 `background` 단축 속성으로 배경색을 지정하므로, 구분선 규칙에서 배경색을 함께 지정하면 강조 색이 사라진다.

**차수별 카드의 인원 칩**: 저장 이미지에서 칩 안의 이름이 금액 아래로 밀려 내려가며 레이아웃이 깨졌다. 칩이 `flex` 아이템이라 폭이 조금만 좁아져도 줄어들고, 그 안의 이름 텍스트가 줄바꿈되는 구조였다. 칩에 `flex: none`과 `white-space: nowrap`을 지정해 칩 단위로만 줄바꿈되도록 고정했다. 이름도 익명 플렉스 아이템으로 남기지 않고 `span`으로 감쌌다.

## 8. 임시 저장 호환

`useDrafts.saveDraft`가 `roundsEnabled`를 함께 저장한다. 기존에 저장한 내역에는 이 값이 없으므로 불러올 때 `false`로 처리한다. 메뉴의 `round` 값 역시 없으면 `1`로 보정되므로 이전 저장 내역을 그대로 사용할 수 있다.

## 9. 스타일 관련 주의사항

`src/styles.css`의 결과 표는 `td:nth-child(N)` 선택자로 열 정렬과 줄바꿈을 지정한다. 차수 열이 생기면 이 번호가 한 칸씩 밀리므로, 표에 `has-round` 클래스가 있을 때 적용되는 재정의 규칙을 추가했다. 앞으로 결과 표에 열을 추가하거나 제거할 때는 두 규칙을 함께 확인해야 한다.

참여자 행에는 원래 `.person button { margin-left: auto; }` 규칙이 있어 행 안의 모든 버튼에 적용됐다. 손잡이와 이름 버튼이 늘어나면서 이 규칙이 오작동하므로, 삭제 버튼에만 적용되도록 `.person .person-remove`로 좁혔다.

이름 입력창은 모바일에서 글꼴 크기를 16px로 지정한다. 그보다 작으면 iOS에서 입력 시 화면이 자동으로 확대된다.

- `src/styles.css`: 차수 UI, 정렬 버튼, 드래그 손잡이, 이름 수정 입력창, 차수별 카드, 표 열 재정의, 반응형 대응

## 12. 남은 확인 사항

1. 실제 모바일 기기에서 참여자 목록 드래그와 페이지 스크롤이 서로 방해하지 않는지 확인
2. 실제 모바일 기기에서 이름 수정 시 키보드가 올라오며 목록이 가려지는지 확인
3. 차수가 4차 이상으로 늘어났을 때 좁은 화면에서의 차수 버튼 줄바꿈 확인
4. 차수별 정산 금액 PNG 저장 시 참여자 수가 많은 경우의 이미지 높이 확인
